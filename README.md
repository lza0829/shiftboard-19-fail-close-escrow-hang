# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（全仓同时仅一单进行中，发起即按当前在途重快照并整批入托管）→ 完成交班整批过户 → 交班对账报告与清单/批次同源

### 失败—解冻—重开闭环

- 发起交班时按**发起时刻**重快照交班方名下仍“在途”的批次，写入挂本单 id 的独立清单表（含业务键快照），并把这些批次整批置为“托管中”、写入托管集合；双方班次上锁为交班中/接班中。
- **失败关闭**（`POST /api/handovers/{id}/fail`，或完成时同源校验不过自动失败）在同一事务内完成：
  - 以不可变清单为权威集合，把每一批强制归位交班方“在途”（覆盖托管中、托管行丢失、已被部分过户三种情形）；
  - 清空本单托管，杜绝托管悬空/孤儿托管批；
  - 释放进行中锁：交班方恢复值班中、接班方恢复交班前状态（默认空闲）；
  - 交班单固化关闭快照列（`closed_at / closure_reason / released_lock / escrow_returned_count`），并向不可变事件表追加“交班失败关闭”事件（事件表带禁更新/禁删除触发器）。
- 失败单**禁止再完成、禁止再失败关闭**（接口返回 409），只能重开新单；新单重新快照、清单挂新单 id，绝不复用或复活失败单旧清单。失败单与新单都在交班记录留档。
- 解冻后允许立即开新单；期间已结清/已冻结的键不进新快照，已结清键永不被再次过户。
- 总览的进行中交班数、锁定班次数、托管批次数同源，并返回 `锁托管同源` 校验位。

### 接口一览（/api 前缀）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/handovers/start` | 发起交班：重快照 + 入托管 + 上锁 |
| POST | `/handovers/{id}/complete` | 完成交班：整批过户；不一致则同事务失败关闭 |
| POST | `/handovers/{id}/fail` | 人工失败关闭（同事务解冻/归位/清托管） |
| POST | `/batches/{id}/settle` | 在途批结清（托管中拒绝） |
| POST | `/batches/{id}/freeze` | 在途批冻结，冻结批不进新快照 |
| POST | `/batches/{id}/unfreeze` | 解冻回在途，可立即被新单纳入 |
| GET | `/dashboard` | 总览，含托管/锁计数与同源校验 |

## 界面约定

页面文案全部中文；入口：总览 / 班次 / 在途批次 / 交班办理 / 交班记录 / 交班对账。
